# 回帰ハーネス

回帰ハーネスは、既存の導線やデータの不変条件が、変更後も壊れていないかを手動で実行して確認するための入口です。現段階ではブラウザ操作の自動化は行わず、Docker内のRailsテストを中心に確認します。

## 実行

Docker Desktopを起動し、プロジェクトのルートで実行します。

```sh
bin/verify
```

このコマンドは、次を順番に実行します。

1. テストDBを準備する
2. 全Railsテストを実行する
3. Zeitwerkの自動読み込みを確認する
4. 差分の空白エラーを確認する

途中のコマンドが失敗した場合はそこで停止します。最後に `Regression harness passed` が表示されれば、コマンドで確認する範囲は成功です。

通常のテストだけを実行したい場合は、従来どおり次を使います。

```sh
docker compose run --rm -e RAILS_ENV=test web bin/rails test
```

`bin/ci` はCI向けの既存入口、`bin/verify` は開発中に任意のタイミングで手動実行する回帰確認の入口です。どちらもテスト用DBを使い、開発DBのデータは変更しません。

## Railsで固定している確認範囲

全テストには、次の導線と不変条件が含まれます。

- ログイン、初期設定、2アカウントでのWedding共有
- 資料の保存、添付、再解析、候補確認、候補承認
- タスクの追加・編集・削除、期限・開始日・担当・状態・カテゴリの絞り込み
- タスクの週／月ガント、一括変更、出典へのリンク
- ゲスト、世帯、出欠、招待数・出席数、引き出物
- BudgetItem、MoneyMovement、見込収支、入出金状態
- 検討・決定、候補、費用・タスクとの関連付け
- Excel初回移行の検証、行単位警告、重複防止、全体ロールバック
- Wedding単位のデータ分離、権限、CSRF、暗号化
- 資料削除後の登録済みデータ保持と出典保持
- AI候補の無断確定防止、再送時の重複防止、二重送信防止

## 画面を手動で確認する場合

Railsテストが成功していても、表示文言やレイアウトの崩れは残ることがあります。画面変更を含む場合は、`bin/verify` の後に開発環境を起動して、次を確認します。

```sh
docker compose up -d
```

- PC幅でサイドバー、ダッシュボード、タスク一覧、資料、ゲスト、お金、ガントを開く
- スマホ幅でサイドバーを開閉し、一覧が横にはみ出さないことを確認する
- スマホ幅でヘッダーのハンバーガーメニューをタップし、ナビゲーション、作成ボタン、設定、ヘルプ、ログアウトが縦に表示されることを確認する
- メニュー表示中に背景をタップする、Escキーを押す、またはナビゲーションリンクを選ぶとメニューが閉じることを確認する
- メニュー表示中に本文が横スクロールせず、メニュー内だけ必要に応じて縦にスクロールできることを確認する
- タスク一覧が区切り線中心のコンパクトな行になり、一括変更がメニュー内にまとまっていることを確認する
- 資料・ゲスト・お金・検討・決定・ダッシュボードの一覧が同じ余白と行間で表示されることを確認する
- タスク一覧が他の一覧と同じページスクロールで表示され、絞り込みモーダルを開いて初期状態と閉じる操作を確認する
- ゲスト・お金・検討・決定・資料の絞り込みを開き、状態・方向・担当などの条件を変更できることを確認する
- ゲスト一覧の「未設定」「出席」などの状態がドットと文字で読み取れ、ゲスト編集の役割チェックが詰まりすぎずに並ぶことを確認する
- ゲスト管理のスマホ表示で、個人・世帯・席次・引き出物・食事の5タブが2段に収まり、「食事」まで横スクロールなしで見えることを確認する
- ご祝儀区分の作成画面で、世帯未設定時の自動適用と適用順の案内が見え、必要なときだけ折りたたみを開けることを確認する
- ゲスト編集画面で、食事の個別設定が任意設定として見つけられ、標準セットを使う場合は開かなくてよいことを確認する
- 資料登録から候補確認、候補承認までを確認する
- ゲストの招待数・出席数と世帯表示を確認する
- ガントの今日位置、月またぎ、期間移動、バーのドラッグによる日程変更とクリック編集を確認する
- 2つ目のアカウントで同じWeddingのタスク・資料を確認する

卓の配置を実データなしで確認する場合は、開発環境にログインした状態で `/seating_tables/layout_preview` を開きます。サンプル卓4件でドラッグ、タッチ、矢印キー、自動配置へのリセットを確認でき、ここでの変更は保存されません。実データの保存と変更履歴は、架空の卓を用意したうえで通常の「卓の位置を編集」画面から確認します。

画面確認に使うデータは架空のものに限定し、確認後に削除します。開発用プレビューはデータを作成しません。スクリーンショット比較やブラウザ自動化は、Railsの回帰確認が安定した後の次段階です。

## 環境とデプロイ

ローカル検証に必要なのはDocker Desktopだけです。初回は次を実行します。

```sh
bin/setup
```

`bin/verify` の追加によってDocker Composeのサービス構成や本番用イメージは変更されません。デプロイ手順は既存の [docs/deployment.md](deployment.md) に従い、デプロイ前にローカルで `bin/verify` を実行してください。
