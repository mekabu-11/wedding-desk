# 個人利用から無料提供へ移るデプロイ計画

更新日: 2026-09-11
対象ブランチ: `codex/wedding-management-v1`

## 結論

まずは自分たちの結婚式準備で使い、動作と入力の流れを確認する。その後、招待制の少人数ベータを経て、利用者が料金を払わない無料プランとして公開する。

公開先は、現在のRails/Docker構成をそのまま活かせる **Render（Web）＋Supabase（PostgreSQL・Storage）** を第一候補にする。個人利用ではローカルDockerを正本にし、外出先から使う必要が出た場合だけRender Free＋Supabase Freeを試験環境として使う。一般公開時は無料枠のまま運用せず、Renderの有料Web・Background WorkerとSupabase Proへ切り替える。

「利用者に無料」と「運営費がゼロ」は別である。AIを有効にする場合は、利用者数に比例してAPI費用も増えるため、無料公開前にAIの利用制限を決める。

## 段階ごとの構成

### 1. 個人利用：手元Docker

最初の正本はMac上のDocker Composeに置く。

- Web、PostgreSQL、Solid Queue workerを現在の `compose.yaml` で起動する
- 添付ファイルは `storage_data` volumeに保存する
- 外部AI送信は無効のまま、手動登録とサンプル登録を中心に使う
- DB、添付ファイル、`SECRET_KEY_BASE`、`AR_ENCRYPTION_*` を別媒体へバックアップする
- スマホでも使う場合は、同じネットワークまたはTailscaleなどの非公開経路から接続する。公開ポートを直接開けない

この段階の目的は、実際の準備で「資料を登録する → やること・ゲスト・お金・検討を確認する → 変更履歴を見る」流れが無理なく続くかを確認すること。機能を増やす前に、入力の手間、スマホのメニュー、変更履歴、バックアップ復元を確認する。

### 2. 個人用の遠隔試験：Render Free＋Supabase Free

外出先のスマホから同じURLで使いたい場合は、リポジトリにある `render.yaml` を使って試験環境を作る。

- Render Web Service：Dockerfileを使ってRailsを起動
- Solid Queue：`SOLID_QUEUE_IN_PUMA=true` でWebプロセス内に同居（個人試験用）
- Supabase PostgreSQL：`DATABASE_URL` にSession poolerを設定
- Supabase Storage：Active Storageの添付先としてS3互換設定を指定
- ログイン：`APP_EMAIL` と `APP_PASSWORD` は初期アカウント作成用。Gitには保存しない

Render Freeは15分間アクセスがないと停止し、次のアクセスで起動待ちが発生する。ローカルファイルも再起動・再デプロイで失われるため、添付ファイルをRenderのディスクへ保存しない。Supabase Freeは7日程度の低活動でプロジェクトが停止する可能性があり、自動バックアップもない。したがって、この段階は実データを置く場合でも、毎日バックアップを取り、障害時にローカルへ戻せることを確認したうえで使う。

### 3. 招待制ベータ：5〜10組

他の人に使ってもらう段階では、無料枠のまま一般公開せず、招待した少人数だけにURLを渡す。

- Renderの有料Web Serviceを常時稼働させる
- Solid QueueをRender Background Workerへ分離する
- Supabase ProでDBを運用し、日次バックアップを有効にする
- 添付はSupabase Storageへ保存し、Railsの認証済みダウンロードだけを許可する
- カスタムドメイン、HTTPS、エラーログ、稼働監視を設定する
- `pg_dump` とStorageの復元を月1回テストする
- 登録、ログアウト、データ削除、CSVエクスポート、2アカウント共有を実際の利用者で確認する

この段階で、利用者のデータを預かる運用が成立するかを判断する。問題が出たら公開範囲を広げず、入力やバックアップを先に直す。

### 4. 無料提供：一般公開

「無料で売り出す」は、利用者から料金を取らずにサービスとして公開する段階と定義する。公開前に次を実装・確認する。

- 招待制の初期アカウント作成から、公開用のサインアップ・メール確認・パスワード再設定へ移行する
- アカウント、Wedding、2人のメンバー、添付ファイル、変更履歴を削除できる導線を用意する
- 利用規約、プライバシー、問い合わせ先、障害時の連絡方法を用意する
- 無料プランの上限を決める（Wedding数、添付容量、資料件数、AI整理回数、保存期間など）
- AIは初期状態で無制限にしない。明示的な実行操作、利用回数上限、送信対象の説明、失敗時の課金防止を用意する
- レート制限、総当たり対策、監査ログ、エラー通知、DBとStorageの復元手順を用意する
- 実際の個人情報・画像・PDFを扱う前に、暗号化キーの保管と復元を確認する

一般公開時も、既存の「1 Weddingにつき最大2アカウント」という設計は当面維持する。大人数のゲスト管理は、Wedding内のゲスト人数上限と添付容量を別に測定してから決める。

## 料金とサービスの判断

2026-09-11時点の公式情報では、Render Freeは個人プロジェクト向けだが、本番利用を推奨しておらず、15分のアイドル停止と一時ファイルシステムがある。[Render Freeの制限](https://render.com/docs/free) と [Renderの料金表](https://render.com/pricing) を参照する。

Supabase Freeは、DB 500MB、ファイルストレージ1GB、転送5GBで、自動バックアップがなく、1週間の低活動で停止する。[Supabaseの料金表](https://supabase.com/pricing) と [Freeプロジェクトの停止条件](https://supabase.com/docs/guides/platform/free-project-pausing) を参照する。

そのため、判断は次の通りにする。

| 段階 | 推奨構成 | 目的 | 扱い |
| --- | --- | --- | --- |
| 個人利用 | ローカルDocker | 正本を安全に持つ | 無料。バックアップ必須 |
| 個人遠隔試験 | Render Free＋Supabase Free | スマホ・公開URLの試験 | 無料。停止・無バックアップを許容できる範囲だけ |
| 招待制ベータ | Render有料Web＋Worker＋Supabase Pro | 少人数の実運用 | 運営費を負担して安定性を確保 |
| 無料一般公開 | 招待制ベータと同じ構成＋運用機能 | 利用者0円で提供 | 運営費・AI費用を上限管理 |

月額費用をほぼゼロに抑えたい場合は、一般公開ではなく招待制ベータまでに留める。無料枠だけで、結婚式の個人情報や原本ファイルを預かるサービスとしての可用性・復元性を保証することはできない。

## 公開前の判定条件

次の条件を満たすまで一般公開しない。

- `bin/verify` と本番相当のassets生成が成功する
- DB・添付・暗号化キーを別々にバックアップできる
- 新しい環境へDBと添付を復元し、暗号化済み本文を読める
- RenderのWebとWorkerを別プロセスで起動できる
- Supabase Storageの認証済み保存・取得・削除を確認できる
- 外部AIを使う場合の送信同意、利用上限、障害時の再試行を確認できる
- 個人利用、招待制ベータ、一般公開の各段階で、停止・退会・データ削除の手順がある
