# 実装範囲：テキストからタスクまで

2026-09-06追記：手動タスク追加、開始日、担当/今週/期限超過の絞り込み、移行用JSONからのタスク取り込みを追加した。詳細は `task-import.md`。以下の当初MVP範囲に対する追加実装として扱う。

承認された最初の範囲「資料登録 → AI解析 → 根拠付き候補の確認 → タスク一覧」を実装する。

## 実装済みの契約

1. 登録日時と連絡日時を分ける。連絡日時は省略できる。
2. 本文の完全一致重複は同じWedding内で防止する。異なるWeddingに同じ資料を登録できる。
3. AIの候補はすべて未確認。原文と期限・担当を確認してチェックするまで反映しない。
4. 不明な担当は未設定。日付だけの期限と時刻付き期限を分ける。
5. 承認・見送りは同じ候補に対して一度だけ有効。確認済みタスクを編集できる。
6. 再解析では同じ内容・根拠の候補を重複作成しない。手修正済みタスクを更新しない。
7. 一時通信障害は最大3回まで試行。その他は失敗を明示する。5分以上停止したジョブは画面から再開できる。
8. 原資料の削除は関連する候補・解析履歴を削除する。承認済みタスクは残し、元資料が削除済みであることを表示する。画面で影響を示し、明示チェックを要求する。
9. ログイン済みでも、別所有者の資料・候補・タスクを参照・変更できない。

## 段階的に追加するもの

PDF・画像・OCR、見積と金額比較、決定事項、回答待ち、複数資料間の同一依頼の関連付け、候補の一括確認、原文の版管理、プロジェクト削除画面。

現在は再解析で文言が変わった候補や、別資料に再掲された同じ依頼の意味的重複は自動統合しない。確認時に不要な候補を見送る。見送りの解除UIは実装済みで、候補の詳細画面から検討中へ戻せる。

変更履歴の全版保存は次段階。候補と引用の原形は残すが、タスクの各手修正の履歴は保存しない。

## 設計案からの実装上の整理

- フロントエンドはRailsビューとCSS。今の範囲はサーバー側フォームで完結するため、TailwindやHotwireの導入を保留。
- 分析状態はAnalysisRunに置き、候補の確認状態とは別に管理する。`completed` は「解析完了」であって「利用者の確認完了」ではない。
- 日付・時刻はAsia/Tokyo固定。多地域対応は次段階。
- 原文の編集は不可。修正内容は別の資料として登録する。手修正したタスクは維持する。
- 初期アカウントはDocker経由のbootstrapコマンドで作成。管理者は設定画面で2人目のログインを追加できる。パスワード再発行・招待メールは対象外。

機能が動くことと、AIが実資料を十分正確に読めることは分ける。後者は利用者のAPI設定と匿名化実資料で今後検証する。
